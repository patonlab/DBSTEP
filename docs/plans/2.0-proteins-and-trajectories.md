# DBSTEP 2.0: residues in proteins and trajectories

Status: steps 1-5, 7 and 8 done for 2.0.0; step 6 (MDAnalysis reader) deferred. Boltzmann weighting of conformer ensembles was added alongside (dbstep/ensemble.py). Tracks the work needed to compute buried volume and
Sterimol parameters for a chosen residue inside a protein (PDB input) and along trajectories.

## Goals

1. `dbstep protein.pdb --residue A:45 --atom CA --vbur` works on a full-size protein in
   seconds, with results identical to extracting the same atoms to an XYZ file and running
   the existing code.
2. Choose what counts as "environment": drop waters, drop other hetero groups, exclude the
   residue itself (only other residues occupy space), or keep only the residue itself.
3. Run the same measurement over every frame of a trajectory and write one row per frame.
4. Never build a grid around the whole protein.

Non-goals for 2.0: mmCIF input, solvent-accessible surfaces, per-residue decomposition of
%V_bur, GUI/PyMOL support for proteins beyond what already exists.

## Why 2.0.0 rather than 1.3.0

The protein/trajectory features themselves are additive and would fit a minor release. The
case for 2.0.0 is that we should ship a small set of deliberate breaking changes at the
same time, so users only adjust once:

| Breaking change | Why now |
|---|---|
| Drop Python 3.9, add 3.14 | 3.9 reached end of life in October 2025; argparse and typing niceties need 3.10+ |
| Migrate `optparse` to `argparse` | Sub-options for residues/frames need argument groups and better validation; help output changes |
| `Mol_Vol` reports the volume of atoms within the cutoff when a cutoff is active | Semantics change for any run that uses `--cutoff`, implicit for PDB input |
| `--exclude` accepts index lists and residue selections | Argument type changes in the Python API (`exclude` may be a list) |
| Remove the unadvertised `rdkit` extension string and route RDKit mol objects through a public `dbstep.from_rdkit()` helper | Cleans the type-dispatch in `read_input` before adding a third input family |

If we decide against these, the feature work below ships as 1.3.0 unchanged.

## Architecture

The guiding rule: everything downstream of parsing stays as it is. A protein run is
"parse, select atoms, crop, then the existing pipeline on a small atom set".

```
file ──► parser (XYZ/SDF/cube/cclib/PDB/trajectory frame)
            │  ATOMTYPES, CARTESIANS (+ per-atom metadata for PDB)
            ▼
        selection  (residue/atom names ──► atom1/atom2 indices; water/het/self filters)
            │
            ▼
        radial crop (keep atoms within cutoff of atom1; spec atoms always kept)
            │
            ▼
        existing pipeline: translate ──► rotate ──► max_dim ──► grid ──► buried_vol / sterimol
```

### New and changed modules

| Module | Change |
|---|---|
| `dbstep/parse_data.py` | Add `PDBParser(DataParser)`; add `get_pdb_models()` for multi-MODEL files; `DataParser` gains an optional `METADATA` dict of per-atom arrays and a generic `keep(mask)` method that filters `ATOMTYPES`, `CARTESIANS`, `METADATA` together |
| `dbstep/selection.py` (new) | Residue/atom-name resolution, water/het/self masks, radial crop. Pure functions over arrays; no knowledge of options |
| `dbstep/trajectory.py` (new) | Frame iterators: multi-MODEL PDB, multi-frame XYZ (reuses `_parse_xyz_boundaries`), and an optional MDAnalysis-backed reader for DCD/XTC/TRR/NetCDF |
| `dbstep/Dbstep.py` | Call selection and crop between `read_input` and `_check_num_atoms`; new options; residue label in output; frame loop in `main()` next to the existing multi-structure loop |
| `dbstep/writer.py` | CSV writer for multi-row outputs (frames, `--residue all`) |
| `dbstep/constants.py` | Water residue names, standard amino acid names, per-residue default Sterimol axes |

### Radial crop (`selection.crop`)

Exact for buried volume. An atom can only occupy points inside the measurement sphere if
its scaled vdW sphere intersects it, so keeping every atom with

    |r_atom - r_atom1| <= cutoff,   cutoff = 1.1 * R_max + 0.5 * shell + SCALE_VDW * max(radii) + grid

loses nothing (`R_max` is the largest radius of a scan, `shell` the `--vshell` width; the
extra grid spacing absorbs rounding in `max_dim`). For Sterimol the crop is a documented
limit: L, Bmin and Bmax are measured over atoms within the cutoff, so L <= cutoff + r_vdw.
`Mol_Vol` becomes the volume of the kept atoms and the column header says so
(`Mol_Vol(cut)`) whenever a cutoff is active.

Implementation: `scipy.spatial.cKDTree(CARTESIANS).query_ball_point(atom1, cutoff)`;
spec atoms are appended to the kept set; indices are remapped exactly as `exclude_atoms`
already does. The crop runs before `max_dim`, so the grid box scales with the cutoff, not
the protein.

Exposed as `--cutoff <Å>` for any input format (useful for large ligands, MOFs, clusters).
For PDB input the default is `auto` (the formula above); `--cutoff none` disables it.

### PDB parser

Fixed-column parsing of `ATOM`/`HETATM` records (columns are 1-based, PDB v3.3):

| Field | Columns | Notes |
|---|---|---|
| record | 1–6 | `ATOM` or `HETATM` |
| serial | 7–11 | kept for error messages only |
| atom name | 13–16 | stored stripped; spacing distinguishes `CA` (alpha carbon) from calcium |
| altLoc | 17 | keep blank or `A`; others dropped, count reported in verbose mode |
| resName | 18–20 | |
| chain | 22 | |
| resSeq | 23–26 | |
| iCode | 27 | |
| x, y, z | 31–54 | |
| element | 77–78 | fallback: first alphabetic character(s) of the atom name using the column-13 rule |

`MODEL`/`ENDMDL` delimit frames; `get_pdb_models()` returns boundaries like the XYZ and SDF
helpers, so `--structure` and the frame loop reuse the same mechanism. `TER`, `ANISOU`,
`CONECT` and everything else are ignored. Metadata arrays: `record`, `name`, `resname`,
`chain`, `resseq`, `icode`, `element`, plus a derived `resid` string `"A:45"` / `"A:45A"`.

### Selection syntax

```
--residue A:45          chain A, residue 45  (insertion code: A:45A)
--residue 45            first chain containing residue 45
--residue A:45,A:46     several residues form "self" (e.g. a disulfide pair, a ligand + residue)
--residue all           loop over every standard amino acid residue (or every residue with --nohet off)
--atom CA               atom1 by name within the residue (default CA)
--atom2 CB              atom2 by name (default: CB; HA for Gly; falls back to N with a warning)
--nowater               drop HOH/WAT/TIP3/TIP4/SOL/DOD residues
--nohet                 drop HETATM records other than the selected residue (ligands, ions)
--exclude-self          selected residue keeps spec atoms as zero-radius ghosts, contributes no volume
--self-only             keep only the selected residue (equivalent to today's extracted-XYZ workflow)
--chain A               restrict environment to one chain
```

Python API mirrors the flags:

```python
import dbstep.Dbstep as db
mol = db.dbstep("1abc.pdb", residue="A:45", atom="CA", atom2="CB",
                volume=True, sterimol=True, nowater=True, exclude_self=True)
mol.bur_vol, mol.L, mol.Bmin, mol.Bmax, mol.resid   # "A:45 LEU"
```

`--atom1/--atom2` (numeric, file order) keep working on PDB input for users who prefer them.

### Trajectories

Frames are handled by the same loop that handles multi-structure XYZ/SDF files: each frame
becomes a `dbstep(...)` call on a copy of the options (already the case since 1.2.0).

| Input | Reader | Dependency |
|---|---|---|
| multi-MODEL PDB | `get_pdb_models()` | none |
| multi-frame XYZ | existing `_parse_xyz_boundaries` | none |
| DCD, XTC, TRR, NetCDF, plus a topology (PDB/PSF/GRO) | `trajectory.MDAnalysisFrames` | `mdanalysis` extra (`uv sync --extra traj`) |

Options: `--frames start:stop:stride` (0-based, Python slice semantics), `--topology file`
for coordinate-only formats, `--csv out.csv` to write one row per frame/residue with the
columns of the printed table plus `frame`, `time_ps` (when available) and `resid`.

The crop is recomputed every frame because neighbours move. Per-frame cost is one cropped
grid build; for a 1000-frame trajectory at the default spacing this is minutes, not hours.
Selection by residue name/atom name is resolved once from the topology and reused as
indices, so frames only need coordinates.

## Testing strategy

Fixtures (all small, checked in under `tests/pdb_files/`):

- `1crn.pdb`: crambin, 327 heavy atoms plus waters, a real structure with chains, TER and
  HETATM waters. Freely redistributable.
- `ala5.pdb`: a capped penta-alanine with hydrogens (about 60 atoms), small enough that a
  grid over the whole molecule is feasible. Generated once and committed.
- `ala5_traj.pdb`: 10 MODELs of `ala5.pdb` with a deterministic side-chain jitter.
- Synthetic PDBs written at test time from `dbstep/data/*.xyz` to test column handling,
  altlocs, insertion codes, element inference and the `CA` vs calcium case.

Test layers:

1. **Parser unit tests** (`tests/test_pdb_parser.py`): columns, element fallback, altloc
   policy, insertion codes, MODEL boundaries, water detection, serial gaps, files without
   element columns.
2. **Exact equivalence** (`tests/test_protein.py`): for a set of residues in `1crn.pdb` and
   each combination of `--nowater`/`--exclude-self`/`--self-only`, take the atom subset the
   PDB path keeps after filtering and cropping, write it to a temporary XYZ with the
   remapped atom indices, and run the existing XYZ path. Same atoms, same spec atoms, same
   grid: L, Bmin, Bmax, %V_bur and %S_bur must match to floating-point precision. This
   pins down parser, selection, remapping and crop bookkeeping in one test.
3. **Crop invariance** on `ala5.pdb`: cropped PDB run versus the XYZ of the whole peptide
   with numeric `--atom1/--atom2`. %V_bur agrees within grid tolerance (0.05); classic
   Sterimol is identical when all contributing atoms lie within the cutoff; a run with
   `--cutoff none` is bit-identical to the whole-peptide XYZ run.
4. **Semantics**: `--self-only` equals the XYZ of the extracted residue (today's workflow);
   `--exclude-self` %V_bur <= full %V_bur; `--nowater` changes results only when a water is
   inside the cutoff (assert both a residue where it does and one where it does not);
   glycine default axis; error messages for unknown residue/atom names.
5. **Scale guard**: generate a synthetic 60,000-atom PDB (tiled copies of crambin) at test
   time; assert the run finishes under a time budget and that the grid point count is the
   same as for the single copy.
6. **Trajectories**: `ala5_traj.pdb` frames give the same values as running each MODEL
   extracted to its own file; `--frames 2:8:2` selects frames 2, 4, 6; CSV has one row per
   frame with the expected columns; MDAnalysis tests are skipped when the extra is not
   installed and run in one extra CI job that installs it.
7. **CLI** (`tests/test_cli.py`): one end-to-end run per new flag group, plus a check that
   `--residue` on a non-PDB input fails with a clear message.

## Risks and open questions

- **Hydrogens.** Crystal structures usually lack them. Results on a raw PDB differ from a
  protonated model. Recommend `--sambvca` (heavy atoms, Bondi × 1.17) as the default
  advice for crystal structures and document how to protonate first (PDBFixer, reduce).
  Question: should PDB input default to `--noH` semantics? Proposal: no, but print a
  one-line notice when a PDB contains no hydrogens.
- **Sterimol in a pocket.** L measured from CA along CA→CB through the environment is a
  "how far is the wall" quantity rather than a substituent length; it is well defined but
  needs a paragraph in the README so nobody compares it with Verloop values.
- **Alternate conformations and occupancy.** Keeping altloc A only is the usual choice;
  an `--altloc B` option is cheap if needed.
- **Multiple chains with the same residue number.** `--residue 45` without a chain is
  ambiguous in multimers; error out and list the candidates rather than guessing.
- **Scan mode and crop.** `--scan` uses the largest radius for the cutoff; `--vshell` adds
  half the shell width. Both covered by the formula, but the tests in step 1 must include
  them.
- **Grid anchoring.** The grid is anchored at atom1 (translated to the origin), so cropping
  does not move grid points; that is why the equivalence tests can demand exact matches.
  If a future change anchors the grid elsewhere, the tests will catch it.
- **MDAnalysis is heavy** (and pulls NumPy pins). Keep it strictly optional and never import
  it at module import time.
